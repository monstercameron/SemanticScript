# taskforge-web (EAV port) — IN PROGRESS (X-043)

Multi-module EAV-Steps port of `apps/taskforge-web` (the v0.1 SemanticScript
multi-user todo web app), in the §28.2 project layout.

## Layout (README §28.2)

```
taskforge-web/
  build.sem            # project manifest: identity + target webServer + entry + version pins
  build.sem.lock       # generated by `eavc mod tidy`
  src/
    main.sem           # the app's root module (API handlers) — see status below
    components/main.sem # 10 reusable HTML component render-operations (ported, lint-clean)
    pages/main.sem      # 3 server-rendered page handlers (ported, lint-clean)
```

The `project` entity lives in `build.sem` (not module source); the modules live
under `src/`, with submodules as directories (`components/`, `pages/`). The
toolchain composes the runtime program with `load_project` (build.sem project +
`src/**/*.sem` modules).

## Status

- **components** (10 ops) and **pages** (3 ops) submodules: fully ported to EAV
  (`htmlTemplate` + `html.render`), lint-clean per module. Shared `HtmlFragment`/
  `HtmlTemplate` types are declared once (in components) and used across modules.
- **`src/main.sem`** (the 18-op sqlite/bcrypt/json/session API module): the
  remaining bulk. Its deferred-runtime contracts are staged
  (`sigs/standard.{bcrypt,log,json}.semsig`) and dynamic routing (`:id`/`*`) is
  supported (§14). The current `src/main.sem` is a placeholder pending the full
  18-op port.

## Deferred execution

The HTTP server + sqlite/bcrypt/json/html runtimes are deferred (`target
webServer` lowering, §27), so the project parses + lints clean but is not
codegen'd.
