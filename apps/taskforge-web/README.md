# taskforge-web (EAV port) — COMPLETE (X-043)

Full multi-module EAV-Steps port of `apps/taskforge-web` (the v0.1 SemanticScript
multi-user todo web app), in the §28.2 project layout.

## Layout (README §28.2)

```
taskforge-web/
  build.sem            # project manifest: identity + target webServer + entry + version pins
  build.sem.lock       # generated by `eavc mod tidy`
  src/
    main.sem           # the 18-op sqlite/bcrypt/json/session API module + the webServer entity
    components/main.sem # 10 reusable HTML component render-operations
    pages/main.sem      # 3 server-rendered page handlers (home / dashboard / 404)
```

The `project` entity lives in `build.sem` (not module source); the modules live
under `src/`, with submodules as directories (`components/`, `pages/`). The
toolchain composes the runtime program with `load_project` (build.sem project +
`src/**/*.sem` modules).

The whole composed project parses + lints clean (0 errors, 0 warnings):

- **31 operations** total (18 API + 10 components + 3 pages), matching the v0.1

- **16 routes** on the `taskForgeWebServer` webServer entity, matching the v0.1

### Porting notes (semsc → EAV)

- `authority OP action resource` rows have no EAV equivalent (EAV has only
  capabilities, and effect coverage is **transitive** — every op on a call path
  must hold a covering `uses` of its own). They are converted to synthesized
  capabilities, and each handler that transitively opens the database is granted
  the file/filesystem `uses` it inherits from `openOrReuseDatabase`.
- `bind ok/value` → call `out`; `bind error` + `branch error source` → `catch` +
  `branch ifError ... goto`; `ignore` → `discards`; `storage module` →
  single-line storage; `literal`+`literalSource` → storage+`literalSource`;
  `sql body`/`jsonBody` → `body sql`/`body json` islands; `set storage` → `set`;
  resource defers → `cleanup` entities (owns/cleanedBy); transaction-rollback
  action defers are dropped (EAV `defer` is handle-scoped; the explicit
  BEGIN/COMMIT carry the transaction boundary).

## Deferred execution

The HTTP server + sqlite/bcrypt/json/html runtimes are deferred (`target
webServer` lowering, §27), so the project parses + lints clean but is not
codegen'd. Validated by `test_app_taskforge_web_full_port`.
