# Safety guarantees

Generated by `python tests/suite/conformance.py --write` from `tests/suite/conformance.py`; `tests/test_conformance.py` runs every check below and fails when this file is stale.

Each guarantee states the rules the checker and runtime enforce, the conformance checks that prove them (edits of [a frozen copy of the warehouse example](../tests/suite/conformance/warehouse)), and other tests that prove them too.

## Ownership and moves

- A resource or region-owned value has exactly one owner: an operation, a region, or (for an output) the caller. `give` moves it; after a `give` on any path the name cannot be used again (R513).
- Every owned value is released exactly once on every path: given away, returned, or cleaned by a deferred cleanup (R513). A cleanup is deferred exactly once (R510).
- A `let` copies only plain values; a second name for a String, list, or record is rejected because it would outlive the loan it came from (R514).
- A resource cannot be stored in a collection, because a region releases collections without closing what they hold (R403).
- Two handles are independent values to the checker, so the runtime guards what they share: one file, under any name (links and `..` resolved), is open for writing by at most one handle of the program and never while another handle reads it; readers share it. A conflicting open, `readAll`, `writeAll`, or `remove` fails with `fs.FileError.busy` (D-52).

## Loans and lifetimes

- `lend` is a shared, read-only loan for the duration of the activation; `lendMutable` is exclusive. A value cannot be lent exclusively while any other loan of it is live, and a read loan cannot be turned into an exclusive one (R515).
- A loan to a task lasts from `start` to `join`, including after a `cancel` (D-39, D-44).
- A value borrowed from an input or a region cannot leave the operation that borrowed it, and an output allocated in a region names that region as its owner (R514, R409).

## Structured concurrency

- Every task is started at most once per path and joined exactly once on every path to every return, whether or not it was cancelled; a task group is joined on every path (R510, R512). There is no detached task, so no task outlives the operation that started it, or anything it borrowed from it.
- `cancel` asks a task (and every task it started) to stop and returns at once; the task sees `cancelled` at its next wait. `join` waits for it to stop and delivers its outcome: its output, its error, or the `cancelled` variant of its error type (D-44).
- A task's failure is delivered only at its `join`, to the operation that started it, and must be branched on there (R506). One plain task failing does not cancel its siblings: the parent decides, and must still join each one. A trap in any task ends the program with the trap's stack trace.
- A task group states the one error type its tasks raise (`catch <name> <Type>`, or `catch none` when none can fail; R403). The first task to fail records its error in the group and cancels the group's other tasks; `join <group>` waits for all of them and delivers that error, followed directly by `branch ifError <group>` (R506, D-48). A grouped task's own output is never read (R510).
- A `join` or `cancel` needs its task live on EVERY path that reaches it: started, and not yet joined, on each incoming path, not just on one; a block reached both after a join and without one is rejected (R510, D-50).
- Cancellation is observed at waits (channel operations, sleeps, accepts, reads, child processes, file locks): the wait ends with the `cancelled` variant of its error. Computation between waits runs to its end, so a cancelled task always finishes in a defined state.

## Capabilities and authority

- build.sem states the program's whole authority in `allows` rows. Every capability of every module, including required packages, grants only what an `allows` row covers, within its scope (R408, D-41).
- An effect is performed only through a capability the operation `uses`, declared in the same module. Capabilities cannot be exported or named from another module, so authority cannot be forged or passed between modules (R402, R205).
- A scoped argument written as a literal must lie inside the scope at check time (R408); a computed one is checked before the call at run time, after `..` and links are resolved, and traps outside it (D-38).
- Writing `allows` rows does not grant them: `refined run`, `test`, `bench`, and executable builds start only when every `allows` row of build.sem is listed in the project's `authority.approved`, written by `refined approve` after a person or a trusted pipeline reviews them; otherwise they stop with exit 3 and name what is missing (D-53).

## Errors

- A fallible activation is followed directly by `branch ifError`; its error has the declared type of the target, and an operation raises only its declared type (R506, R403).
- A `match` names every variant of the error exactly once (R509).
- Sending both outcomes to the same block discards the failure, which needs a `rationale` row saying why (filler text is rejected) and `suppresses` rows naming exactly the variants dropped: every variant of the error type, so a variant added later breaks the build instead of vanishing. An activation that handles its failure states `suppresses none`; a cleanup under `onError suppress` names its call's variants (R506, R304, D-54).

## Text and source positions

- Text is read a byte at a time with `string.byteAt`, and every index is checked: an index outside the text is a typed `outOfRange` error, never a read past its end.
- `string.slice` keeps characters whole: a slice that would start or end inside a UTF-8 sequence is `outOfRange` (D-70), so a slice of UTF-8 text is UTF-8 text.
- `string.advancePosition` steps over one whole character and keeps its line and column: a newline starts the next line at column 1 and any other character moves one column, so columns count characters, not bytes. Stepping from outside the text is `outOfRange` (D-71).
- A file path computed at run time (from the command line, say) is checked against the capability's scope when the file is opened; outside the scope the program stops before the file is touched (D-38).

## Deterministic cleanup

- A cleanup is deferred after the value it cleans exists, and exactly once on a path (R507, R510); it runs at every later `return`, `ok` or `error`, newest first, and only once.
- A cleanup's call takes the value with `give`: the value is consumed even if releasing it fails. `onError trap` stops the program; `onError suppress` continues. Every cleanup states a `rationale` row saying why its policy is right (R302).
- A trap runs no more program code, so deferred cleanups are skipped (the state that trapped may be the state they act on). The runtime then releases what the program still holds outside it: files are flushed and closed, connections closed, child processes stopped; the trap message says how many (D-51).
- A cancelled task runs the cleanups of the operations it unwinds through, since cancellation reaches it as an error.

## Region memory

- Every allocation names a region; a region's `capacity` is a hard limit. Allocating past it traps with the region's name before any memory is written, so exhaustion never corrupts memory (A10).
- A region is released at its operation's return, after every task that could use it has been joined; values it owns cannot be returned unless the output names the region as owner (R409, R512).
- Allocation a program can recover from: `arena.remaining(region)` says how many bytes are left, and `arena.ensure(region, bytes)` fails with `arena.ArenaError.exhausted` (carrying what is left) when that much is not free, so a program asks before a step that allocates and takes its own path (D-55).

## Handles and interior mutability

- A target that changes the state of the handle it is given (a file's position or lock, a connection's stream, a listener's queue) takes it `borrowedMutable`, so it is passed with `lendMutable` and no two activations can use one handle at once (R406, R515, D-43).
- A channel is the one shared mutable value: its operations are synchronized and it exists to be used by several tasks, so it is lent with `lend`.

## Collections and iteration

- A table is constant data fixed when the program is checked; it is read only by `forEach` and has no step that changes it. A `forEach` over a table states a `maxIterations` at least its row count (R503).
- A `forEach` over a list reads it on every pass, so inside the loop the list cannot be changed, lent exclusively, or given away (R515). Passing the loop's `maxIterations` at run time traps (D-45).
- A loop's bound may be computed at run time (a list's length, say): any immutable `Int64` value set on every path into the loop before its first pass, back edges included (R503, R507, D-56).

## Trees and symbol tables

- A type never holds itself, by value or inside a collection (R403). A tree is a list of nodes that refer to each other by position: `<Alias> aliasOf Int64` with `<Alias> indexes <List>` makes the alias that list type's only position type, so `get` and `set` take it and a plain `Int64` is refused (R403, D-60).
- A position has no literal; it comes only from `<List>.appendIndexed`, and reading a position the list does not have is `list.IndexOutOfRange`, never a stray read. Recursion over a tree is bounded by `maxRecursion`; deeper traps.
- A map's key is a plain value or a `String` (R403). A `String` key is lent, compared by content, and copied into the map's region when first put, so keys read back live as long as the map (D-61).
- A `forEach` over a map reads its keys in first-put order. Inside the loop the map cannot be changed, lent exclusively, or given away (R515); passing the loop's bound, which may be the map's length read at run time, traps (D-62).

## Positions and stacks

- A list that has an index alias is indexed: `appendIndexed` returns a position, and `get`, `set`, and `getOrTrap` take one. Every list has an identity, given when it is made, and a position carries the identity of the list it came from: used on any other list it is `list.IndexOutOfRange`, never a read of another item (D-100).
- An indexed list only grows: it has no `clear`, `removeLast`, or `truncate`, so a position never names a slot that was emptied and reused (R401, D-100). `<Alias>.toInt64` gives a position's number, for printing and as a key; there is no way back from a number to a position.
- `getOrTrap` (lists) and `string.byteAtOrTrap` are the trapping twins of `get` and `byteAt`: for an index the program has already proved in range, a bad index is a trap rather than an error to branch on (D-101).
- A list of plain items is also a stack: `removeLast` takes the last item off (an empty list is `list.IndexOutOfRange`), and `truncate` cuts the list to a length (D-102).
- An item of a list is read as a view; to change a list or record held in a list, `replace` puts a new item in and hands the old one back owned (for items that are not plain values, as a value of the list's region, which the call names and the runtime checks), so it can be changed and put back (D-105).
- A collection outlives what it stores only if what it stores lives in its region. Text, and text inside records and enum payloads, is copied into the collection's region when stored (lists, maps, sets, channels), so text made in a region that ends first stays readable. A value holding a list, map, set, or channel cannot be copied that way: it must come from a call whose `ownedBy` names the collection's own region, in the same operation (R514, D-107).
- A table is a fixed array: `<table>.length` is its row count and `<table>.rowAt` reads a row by the number its `row` row gives it (1 to n); any other number is `list.IndexOutOfRange` (D-104).
- A `constant` is a named literal of a module (`type`, `value`), read by every operation of the module as an immutable value set on entry; its value is a literal of its type, it cannot be set, and no operation may reuse its name (R403, R411, D-103).

## Not guaranteed

- Deadlock freedom is checked at run time, not statically: a program in which every task waits on another traps with every wait listed (`case:11-concurrency/trap-channel-deadlock`).
- Arithmetic overflow, division by zero, out-of-range conversions, and a list read past its end are run time traps or typed errors, not compile-time errors.
- Capability scopes on computed arguments are enforced at run time only.
- Foreign functions (`ffi`) are limited to numbers and `Bool` with no shared memory; what the C code does inside is outside the language's guarantees.
- Standalone executables include only the core runtime; programs calling host-library targets are refused (R901) rather than built.
- Running out of a region is a safe trap (D-49), not a typed error: every allocation would otherwise be fallible. The trap happens before any memory is written and names the region; a program sizes its regions for what it allocates.
- A grouped task's output is not delivered (`result none`); its failure is, through the group. Use a plain task when the output matters.
- There is no detached task; work that must outlive its operation is not expressible.
